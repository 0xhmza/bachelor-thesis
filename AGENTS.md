## graphify

This project has a knowledge graph at graphify-out/ with god nodes, community structure, and cross-file relationships.

When the user types `/graphify`, use the installed graphify skill or instructions before doing anything else.

Rules:
- When graphify-out/graph.json exists, run `.\graphify.ps1 query "<question>" --budget 1200` before exploring project content. Query returns source locations; open the relevant passages to verify facts. Use `.\graphify.ps1 path "<A>" "<B>"` for relationships and `.\graphify.ps1 explain "<concept>"` for focused concepts. Include this guidance in subagent prompts that explore project content.
- Dirty graphify-out/ files are expected after hooks or incremental updates; dirty graph files are not a reason to skip graphify. Only skip graphify if the task is about stale or incorrect graph output, or the user explicitly says not to use it.
- If graphify-out/wiki/index.md exists, use it for broad navigation instead of raw source browsing.
- Read graphify-out/GRAPH_REPORT.md only for broad architecture review or when query/path/explain do not surface enough context.
- After modifying code, LaTeX or Markdown, run `.\graphify.ps1 refresh`. This project wrapper also indexes LaTeX sections, inputs and citations, which upstream Graphify does not detect. It reuses only semantic extractions whose source hash still matches. Refresh semantic content with the installed Graphify skill when reported stale; never treat an old plan as a current decision.
- A committed graphify-out/graph.json is rewritten whole on every build, so a large diff to it in a pull request is expected. Do not flag it as churn or suggest skipping the graph rebuild or its hooks.

## Project tooling

- `03_Thesis/Thesis_Review-Copy.docx` is generated by `scripts/build_review_docx.py` (the pre-commit hook rebuilds and stages it when thesis sources change). Never edit it by hand; it is the supervisor's review copy.
- Reading status lives in `01_Literature/reading-status.csv`. `literature-index.json`, `Literature-Map.html` and the README status column are generated from it by `.\graphify.ps1 refresh`.
- Run `python scripts/check_project.py` after editing the thesis, the bibliography or Markdown links; it must report 0 errors.
- Record methodological choices in `00_Admin/Decision-Log.md` with evidence before the methodology states them. Organizational files never add thesis content.

## Scripting projects

- Give each new scripting project its own `scripts/<project-name>/` folder.
- Version scripts with folder names `v001/`, `v002/`, etc.; preserve prior versions. Do not use Git branches or tags for script versioning.
- Keep generated files in the version's `output/` folder, excluded from Git and Graphify. Prefer short, standalone scripts.
