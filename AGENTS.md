## Workflow

- **Commit and push after each edit.** When a change is complete (one logical
  edit, checks passed), commit only the files it touched, with a message that
  says what changed and why, and push to `origin main`. Leave other work in the
  tree (for example another project's scripts) unstaged.
- Before committing thesis, bibliography or Markdown-link changes, run
  `python scripts/check_project.py` (must report 0 errors) and
  `.\graphify.ps1 refresh`.
- The pre-commit hook rebuilds and stages `03_Thesis/Thesis_Review-Copy.docx`
  (the supervisor's copy, made by `scripts/build_review_docx.py`). Never edit
  it by hand.

## Thesis

- Main document: `03_Thesis/thesis.tex`; write in its chapters and appendices.
  `03_Thesis/proposal/` is the preserved 5 October snapshot; do not edit it.
- The 13 October supervisor meeting notes supersede conflicting proposal plans.
  Do not invent results or resolve open decisions without evidence.
- Record each methodological choice, with its evidence, in
  `00_Admin/Decision-Log.md` (and its `Decisions/Dnn_*.md` record) before the
  methodology states it. The methodology states rules; numbers that follow from
  applying them belong in the results.
- `_shared/references.bib` is the only bibliography. Check new entries against
  the PDF or a DOI record.
- Passages under revision are marked `\highlight[orange!25]{…}\todo{…}`; keep
  the marks until the author resolves them.
- Files in `03_Thesis/tables/` are generated by scripts (they say so in their
  first line); change the script, not the file.
- Compile the thesis with BibTeX (pdflatex, bibtex, pdflatex, pdflatex), or
  let latexmk select the required passes. The author compiles
  in TeXstudio inside `03_Thesis/`, so test builds go to a copy of the tree
  elsewhere: two builds writing the same `thesis.aux` corrupt it.
- Edit LaTeX with exact-text edits. Never pass it through non-raw Python or
  shell strings: `\todo` and `\ref` turn into control characters. TeXstudio may
  save its stale buffer over an edit while it has the file open: wait a few
  seconds, search the file for the new text, and re-apply the edit if it is
  gone, before building or committing.
- A table sits directly after the paragraph that introduces it, pinned with
  `[H]`, with its caption and label; never collect tables at the end of a
  section. If it does not fit the rest of the page, give each paragraph its own
  table, or keep a short table in the body (counts, examples) and the complete
  one in an appendix. If its content must stay as it is, place it after its
  paragraph as a top float (`[!t]`) so it opens the next page in the same
  section. Look at the rendered pages for large gaps. The body keeps
  the rules and choices; the appendix keeps exact strings and complete lists.
- Organizational files (`00_Admin/`, `01_Literature/`, `04_Study/`) never add
  thesis content.

## Scripts and data

- Each scripting project has its own `scripts/<project>/` folder with versions
  `v001/`, `v002/`, …; a change of behaviour is a new version, and earlier
  versions stay. No Git branches or tags for script versions.
- Generated files stay in the version's `output/` folder, excluded from Git and
  Graphify; back up raw collections separately.
- The app sample rests on the frozen collections in
  `05_Data/raw/app-sample_2026-10-25/` (read-only; hashes in
  `05_Data/raw/README.md`) and the sample in `05_Data/processed/app-sample/`.
  Later work reads these, not a script's `output/` folder. Prefer short standalone scripts
  with unit tests where they decide the sample.

## graphify

The knowledge graph in `graphify-out/` covers the thesis, admin, study and
literature files.

- When the user types `/graphify`, use the installed graphify skill first.
- Before exploring project content, run
  `.\graphify.ps1 query "<question>" --budget 1200`, then open the returned
  locations to verify. Use `path "<A>" "<B>"` for relationships and
  `explain "<concept>"` for one concept. Pass this guidance to subagents.
- After modifying code, LaTeX or Markdown, run `.\graphify.ps1 refresh`. It
  also indexes LaTeX sections, inputs and citations and reuses only semantic
  extractions whose source hash still matches. When it reports stale files,
  re-extract them (`prepare`, chunk files, `import-semantic`, `refresh`); never
  treat an old plan as a current decision.
- Dirty `graphify-out/` files after hooks are expected, and a whole-file diff of
  `graph.json` is normal; neither is a reason to skip graphify.
- Use `graphify-out/wiki/index.md` for broad navigation if it exists; read
  `GRAPH_REPORT.md` only for architecture reviews.
- `.graphifyignore` excludes archives, raw and processed data, PDFs and
  generated outputs from semantic extraction.
