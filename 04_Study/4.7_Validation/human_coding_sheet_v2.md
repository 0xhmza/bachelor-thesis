# Human coding sheets

**Version:** 2 · **Date:** 2026-11-05 · Part of the frozen instrument bundle
(methodology, Reference-Tree Check and Instrument Freeze). Codebook v7; D8, D9, D20.

Two sheets. Both show the coder the unit and the text next to it, never the models'
labels, stances or explanations (Schroeder et al. 2025: shown labels pull human labels
toward them).

## Sheet A — checking a high-stakes label (`human:check`)

Shown: unit ID, unit text, the units before and after, and the axis on which the unit
was flagged ("possible named harm", "possible stance", "protection claim").
Not shown: which model flagged it, model labels, spans or reasons.

| Field | Entry |
|---|---|
| Unit ID; coder; date | |
| Named harm(s): category, status (asserted/possible/denied), span | none / list |
| Scope of each harm: pathway ID(s) whose consequence, data, actor and access fit, or `category` | |
| Generic risk (`L-GEN`) / generic responsibility (`S-GRS`) / reassurance (`C-REA`), with span | |
| Stance(s) per named harm, with target for `S-QUA` | |
| Protection framing and strength, where flagged | |
| Unsure? reason | |

The checked label is final for the reported counts. It is one person's judgement and
is never used as a reference label.

## Sheet B — validation sample (`human:reference`)

Each sampled unit, in the random order of the manifest, coded completely on all axes
of the codebook, by the author and the second coder separately and without model
output. Agreement (α per code) is computed before any discussion; then disagreements
are settled and the reason is recorded.

| Field | Entry |
|---|---|
| Unit ID (from `validation_manifest.csv`); coder; date; minutes taken | |
| Axis A: every node with status and span; harms with scope as in Sheet A | |
| Axis B: stances per named harm; `S-GRS` | |
| Axis C: measures with actor, data, outcome, conditions; framing and strength; `C-REA` | |
| Unsure codes with reason | |
| Settled label after discussion (filled in afterwards) and reason | |

Record the minutes per unit in the second coder's training: they can reduce the sample size (D9, D20).

## Training of the second coder

Before the sample is drawn, the second coder codes 20 units from the policy of an app
outside the sample with the codebook, compares them with the author's coding of the same
units and discusses every difference. These units are not part of the corpus.
