# Open Points for Confirmation

The proposal (`03_Thesis/proposal/proposal.tex`) decides every question left open
after the meeting of 2026-09-04 and the written input of 2026-09-05, so that work
could proceed. The proposal itself carries none of this list — it holds only what
the supervisor asked for. Take this file to the next meeting; each row is a
decision to confirm or overturn. Overturning one changes only the part of the
methodology named in the last column.

| # | Decision made in the proposal | Why | Affects |
|---|---|---|---|
| 1 | **Scope is document and interface analysis, not a user survey.** | The 2026-09-05 input lists only document and interface sources; this settles the question in the meeting notes §8. The scenario survey stays a possible second phase. | Whole methodology |
| 2 | **Knabenhans et al.'s seven harm categories and harm trees are the coding backbone; Citron & Solove's relationship harm is kept as a separate tag** (codebook v3). | One published harm model with a stated baseline; the tag keeps the one Citron–Solove category the list omits. | Coding, axis A; reference trees |
| 3 | **"Highest rated" = ≥ 1,000 ratings, then ranked by average rating**, count as tie-break. | Without a floor, the phrase selects obscure apps with a handful of five-star reviews. | Sampling |
| 4 | **50 apps is the target, not a first pass**; stratified 30 fitness / 20 fertility; separate five-app pilot. | Enough for descriptive prevalence; the fertility stratum is over-represented deliberately. | Sampling |
| 5 | **Walkthroughs on 12 apps**, balanced 6/6 and 3/3 across platforms. | Balance keeps the RQ4 comparisons from being confounded with sample size. Alternative: all 50 apps, smaller document sample. | Walkthrough |
