# Assessment of the App Walkthroughs revision

Date: 3 November 2026. Scope: Claude's four-file draft supplied by the author,
reviewed against the current thesis, D7–D10, the reference model, the operational
protocol and the 13 October meeting. This is a review record, not study results.

## Verdict

The revision was useful, but **not perfectly done or ready to freeze**. Its main
contribution was to explain how walkthroughs support the same harm-tree analysis
as policies. That connection is appropriate. However, the resulting section
contained an unsupported applicability inference and an impossible session order,
and left important measurement and evidence boundaries underspecified. Several
problems were inherited from the protocol rather than introduced by Claude;
writing them into the methodology did not resolve them.

The corrected text is a more defensible proposed method. It still requires the
pilot and the unresolved author/supervisor decisions listed below. No app has
been walked through or new empirical result established in this review.

## What Claude did well

- Kept the app inspection manual and limited the model to subsequent text coding.
- Connected T1–T7 to reference-model nodes and separated three useful outputs:
  task findability, interface text and applicability evidence.
- Used the same coding axes for policy and interface text, supporting RQ4.
- Preserved human decisions, span checks and blind coding rather than treating
  model suggestions as established labels.
- Added the missing Pilot and Analysis labels and moved the task table next to
  its introduction.
- Kept device details, repeat inspection and the proposed policy-coding order
  visibly unresolved. It did not fabricate walkthrough results; the instrument
  test remains explicitly synthetic.

The misleading “only screen wording counts as data” instruction was also removed.
Observable actions/states and reasoned analyst judgments are study records too;
they must remain distinct from verbatim text and from each other. Only checked
text goes into the text-coding model.

The cross-thesis check also found the old synthetic version-5 fixture using the
same missing-export inference and treating an email request as an access barrier.
Its dependent Results and Appendix H passages now explicitly identify the
classifications/counts as historical inputs requiring re-evaluation. The original
fixture and generated tables remain audit evidence; this review does not invent
a replacement session or claim that protocol v7 has been empirically tested.
The current sampling amendment and D15 also now identify the superseded six/six
platform quota and point to the current instrument versions.

## Coherence with the thesis

The final division of work is consistent with the Study Design, Coding Units,
Applying the Trees and Analysis sections:

1. Screens and actions contribute **evidence** to the human applicability record;
   uncertain conditions remain uncertain. They do not establish actual harm.
2. Captured provider UI text and policy text receive the same axes and tree-node
   identifiers through D9's proposed model-assisted stages and human decisions.
3. The protection check asks whether a claimed measure would cut a pathway **if
   it worked as claimed**. Encountering a button is not a test of effectiveness.
4. RQ4 compares matching nodes/claim scopes and separately reports what is direct,
   linked, not found within limits or blocked at the specified decision points.

The thesis states these rules. Protocol v7 supplies the corresponding session,
task and evidence-record fields. D10 and the Decision Log record the corrections
before the methodology; D9 clarifies the two-surface validation boundary.

## Source checks

Checked the original local PDFs, not the digest cards:

- Wharton et al. (1994), Table 5.1, printed p. 106 (PDF p. 131): four inputs and
  questions; printed pp. 109–111 (PDF pp. 134–136): user assumptions, task context
  and action sequences before analysis; printed pp. 113–114: records and stories.
  The individual-process statement on printed p. 109 is supported.
- Malki et al. (2024), PDF pp. 4–5, §§3.3–3.4: triangulation, novice user,
  wiping/reinstallation, tasks, hybrid heuristic inspection and two independent
  inspectors. It supports the precedent, not an assertion that this thesis
  reproduces their entire method.
- Mahatody et al. (2010), manuscript pp. 15 and 20–22: common task questions,
  evaluator expertise, limited comparative validation and potential value of
  recording. The thesis now gives those locators.
- Habib et al. (2020), PDF p. 4, Table 1: minimum action counts for controls.
  This supports counting actions; it does not make this thesis's located route a
  proven global minimum or convert taps into observed user effort.
