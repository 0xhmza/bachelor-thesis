# Literature

Everything the thesis reads lives in this folder, in six entries.

| Path | What it is |
|---|---|
| `library/` | **All full texts**, flat, one file per work: `Author_Year_ShortTitle.pdf` (164 files). There are no topic sub-folders: topic, method stage, priority and reading status are columns in the catalogue |
| `notes/` | One note per paper you have read, same name as its PDF (template below) |
| `catalog/` | The data about the works. `reading-status.csv` is **the reading tracker** (edit the `status` column: `to read`, `skimmed`, `read`, `noted`). `methods-corpus.json` is the catalogue of the 93-work methods corpus (topic, stage, priority, DOI, version, local file). `Methods-Reading-List.md` is the ranked guide to it. `Audit-Sources_2026-11-04.md` records version and source of the files added in the methodology audit. `literature-index.json` and `Literature-Map.html` are generated by `.\graphify.ps1 refresh`; do not edit them |
| `review/` | The systematic literature review: decisions, screening, evidence extraction and the gap search of 23 October |
| `digest/` | The Methods Digest: paper cards, build tools and the finished PDF volumes in `digest/volumes/`. Start with `digest/HANDOFF.md` |

Not here: the raw search runs of the literature review are data and live in `05_Data/Literature Search/`.

## Where a file goes

- A paper, report, book, web capture or supplement is a PDF in `library/`. Save it there directly under its final name; do not collect PDFs in an inbox or in topic folders.
- Something you wrote about a paper is a note in `notes/`.
- Metadata (topic, priority, DOI, status) goes into `catalog/`, never into the file name.
- Generated files stay generated: change the script, not the file.

## One rule

Every paper you cite must have (a) a PDF in `library/`, (b) a row in the reading list below
(or in `catalog/methods-corpus.json` for the methods corpus), and (c) an entry in
`../_shared/references.bib`. No exceptions: that is what stops the bibliography from rotting.

## Naming

- **PDF:** `Author_YEAR_ShortTitle.pdf`, for example `Citron_2022_PrivacyHarms.pdf`.
  - `Author` is the first author's surname, without spaces, hyphens or diacritics (O'Connor becomes `OConnor`, von Elm `VonElm`, Törnberg `Tornberg`). An organisation uses its short form (`APA`, `BfArM`, `Article29WP`).
  - `YEAR` is the year of the version in the file.
  - `ShortTitle` is two to five key words in CamelCase; a hyphen only separates a subtitle (`Gabriele_2020_FitnessTrackerUsers-KnowledgeAttitudes`).
  - A suffix marks what the file is when it is not the full published article: `_published`, `_manuscript` or `_preprint` (two versions of one work), `_supplement` (appendix or instrument), `_excerpt` (part of a book), `_web-capture` (a dated copy of a web page).
  - An edited volume is named after the editor, because the file is the whole book: `Nielsen_1994_UsabilityInspectionMethods-Book.pdf` (the walkthrough chapter of Wharton et al. is Ch. 5, pp. 105–140).
- **BibTeX key:** `lastnameYEARfirstword`, for example `citron2021harms`. The key's year may differ from the file name's when a preprint and the published version differ. The key never changes once cited.
- **Note:** same stem as the PDF, `.md`.
- **Documents about the literature** (guides, decision records, logs) use `Title-Case_YYYY-MM-DD.md`.
